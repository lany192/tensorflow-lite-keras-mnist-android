## 使用模型

将训练生成的模型文件model.tflite拷贝到assets文件夹，供android读取

## 识别数字和小数点

在画布上从左到右依次写下数字或小数点，数字之间留出空隙，点击「识别」即可得到数值。
识别结果下方会列出每个字符，便于区分"切分错了"还是"认错了"。

模型是 11 类单字形 CNN：0~9 加小数点。Python 训练脚本会把 MNIST 与合成的归一化点样本合并；
Android 端负责切分和上下文判断：

1. `InkSegmenter`（纯 Kotlin，不含任何 Android 依赖）把画布按 8 连通域切成数字和小数点候选；
2. 小数点必须小而实心、靠近基线，并夹在左右两个数字之间，否则仍按噪声过滤；
3. `MnistPreprocessor` 对每个字形包围盒做 MNIST 风格归一化，11 类模型最终确认它是数字还是小数点。

`InkSegmenter` 的算法可用 `./gradlew test` 在 JVM 上直接验证，回归用例在
`app/src/test/kotlin/com/github/lany192/mnist/InkSegmenterTest.kt`。

注意：识别精度几乎完全由「笔画宽度 / 数字高度」的比例决定（实测安全区 ≤0.19，0.2~0.25 开始退化，0.3 以上崩塌），
而不是由切分算法或模型决定。笔宽固定为 32px，所以**数字写得大一些、位数少一些，准确率明显更高**：
位数越多，每个数字越小，比例就越容易越过悬崖。界面因此把一次识别的位数上限定为 4 位。

## 数学练习

按小学六个年级随机出题（10 道一组），学生在画布上**手写答案**，提交后识别并判定对错。

- 难度按年级递进；五六年级的题目含小数、分数、百分数，但**当前答案仍构造成整数**。
  识别链路已经支持小数点（例如答案 68 写成 `68.0` 也能按数值判对），但把 `Problem.answer`
  扩展为小数还需要同步修改出题器、跨页传参和 Room schema。
- 提交后是**两次点击**：先显示识别结果让学生核对，确认无误再点「确认」才判定。
  手写识别本身会出错（3 位整串全对率约 77%），这一步是为了不冤枉学生。
- 每组结束时给出成绩与错题回顾，并可「错题再练一遍」。

题目生成全部是**先定答案、再反推操作数**（见 `MathProblemGenerator`），
不做出题后筛选 —— 除法、小数、分数的可行组合太稀疏，筛法要么命中率极低要么根本生成不出。
出题规则由 `MathProblemGeneratorTest` 用独立求值器逐题验算。

## 学习记录与错题本

练习成绩与每一道题的作答明细存在本地 SQLite（Room）里，**不上传、卸载即清除**。

- 「学习记录」页显示按年级分的累计正确率、历史练习列表、错题本。
- **错题本 = 每道题最新一次作答是错的**。所以重做答对之后，该题会自动从错题本消失，
  不需要单独维护"已订正"状态。
- **重做的记录照样写库**（错题本靠它自愈），但**不计入累计正确率** ——
  刚看过答案的题参与统计，这个数字就没有意义了。
- 数据层与界面的边界、以及几个容易踩的坑（SQL 的写法、minSdk 24 的 SQLite 能力上限、
  跨页传题为什么用两个数组），都记在 `AGENTS.md` 的 Persistence 一节。
